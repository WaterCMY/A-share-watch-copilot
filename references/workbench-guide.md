# 本地工作台（Workbench）搭建指南

本地工作台是一个**可选的**可视化看盘层，与 agent 对话互补：agent 负责定时推送与深度分析，工作台负责实时行情与快捷操作。纯前端单页 HTML + 本地 Python 代理，无需云端部署。

> 本文档对应的示例代码 `assets/workbench.example.html` 与 `assets/workbench-server.py` 均为**脱敏版**，所有持仓为虚构示例数据。

## 架构

```
浏览器(workbench.html)  ──HTTP──►  本地代理(workbench-server.py:8801)  ──►  公开行情接口
   │                                    │
   │  localStorage（录入/卖出/调整）       │  读写 positions.json（/api/sync）
   └────────────────────────────────────┘
```

- **前端**：单文件 HTML，JS Tab 切换「📊 个人持仓」「🌐 大盘全景」「🐔 养鸡场（场外基金）」「🧾 整体交易记录」四个视图，无页面跳转。
- **后端**：Python `http.server` 起的本地代理（端口 8801），用 `urllib` 转发公开行情接口、处理 GBK→UTF-8、提供 `/api/sync` 与 `/api/sync_funds` 写回本地档案。
- **同源**：浏览器访问 `http://localhost:8801`，前端与代理同源，避免 `file://` 跨域与 `<a href>` 变下载问题。

## 能力清单

### 个人持仓视图
- 实时行情（每 60 秒刷新），含现价 / 今日涨跌 / 浮盈% / 浮盈额 / 市值。
- 持仓表格 12 列：标的 / 股数 / 现价 / 今日 / 成本 / 浮盈% / 浮盈额 / 市值 / 距支撑位 / 距压力位 / 意图 / 状态；表头可点击排序。
- 每行三个操作：`✕`（删除手动录入项）/ `卖出`（减仓并核算已实现盈亏）/ `调整`（改成本价/股数）。
- 概览统计：总市值 / 浮盈额 / 浮盈% / 风险标的数 / 已实现盈亏。

### 大盘全景视图
- 主要指数：上证 / 深成 / 创业 / 科创 / 标普500 / 纳指 / 恒生 / 恒生科技。
- 市场宽度：涨跌家数 / 涨停跌停数 / 涨停连板（服务端分页聚合，突破单次 100 条限制）。
- 北向资金净流入。

### K线弹窗
- 点击任意标的 → 弹窗，五视图切换：`分时` / `日K(90根)` / `周K(60根)` / `30分(160根)` / `1时(120根)`。分钟线 x 轴显示 `MM-DD HH:mm`。
- 蜡烛图 + MA5/10/20（橙）/ MA120（紫）/ MA250（蓝，周K不足时自动隐藏）+ 量能柱。
- 分时图：价格线 + 均价线 + 量柱。

### 移动端适配
- 纯 CSS 响应式（无需 JS）：窄屏（≤880px）下，三张大表（持仓 / 基金 / 整体交易记录）由横向滚动表格转换为**卡片式**——每行一只标的成一张卡片，`列名:值` 竖排堆叠，名称列作为卡片头，彻底消灭横滑。
- K 线弹窗 SVG 采用 `width:100%` + viewBox 自适应，手机自动缩放。
- 头部纵向堆叠、Tab 横向滚动、概览卡片 2 列、点击区放大，整体读感对齐手机。
- **手机访问**：server 默认监听 `0.0.0.0:8801`，手机连同一 Wi‑Fi 后用浏览器打开 `http://<电脑局域网IP>:8801` 即可（`<电脑局域网IP>` 用 `ipconfig` 查 WLAN 适配器的 IPv4，如 `172.22.1.196`）。仅限私人网络，公共网络勿暴露。

### 养鸡场视图（场外开放式基金）

追踪场外开放式基金，数据独立存放于 `funds.json`，**不与 `positions.json` 混用**。

**与场内持仓的本质差异**：场外基金只有每个交易日收盘后公布的**单位净值**，没有实时价、没有分时/K线、也没有盘中支撑压力位。因此该页**不提供 K 线弹窗与价格提醒**，表格列也相应精简。

- **表格 11 列**：基金 / 份额 / 净值 / 今日 / 成本 / 收益% / 收益额 / 市值 / 类型 / 意图 / **来源**；表头可排序。
- **分销售平台管理**：每只基金带 `source` 字段标记购买平台。
  - 顶部**平台筛选**（全部 / 各平台，选项由数据自动去重生成），概览卡随筛选联动。
  - 筛选下方**平台总览表**：固定展示各平台与合计两级的总市值 / 持有收益 / 收益率 / 今日涨跌 / 基金数，分平台与整体一眼可见。
- **操作**：`＋ 录入基金`（代码/名称/份额/成本净值/类型/平台/意图）、`赎回`（减份额并核算已实现收益）、`调整`（改成本净值/份额）、`🔄 同步到后端`（写回 `funds.json`）。
- 录入/赎回/调整均先存 `localStorage`（三个独立键），刷新不丢；确认无误后再同步落盘。

### 整体交易记录视图

把 `positions.json`（场内持仓）与 `funds.json`（场外基金）里**每一笔 `trades` 记录合并**成一张总账，方便一眼看清全部建仓 / 加仓 / 减仓 / 赎回流水。

- **汇总卡片**：成交笔数 / 累计投入本金（所有买入金额合计）/ 累计赎回收回（所有卖出金额合计）/ 净投入（投入 − 收回）。
- **明细表 10 列**：日期 / 账户·平台 / 类型 / 标的 / 代码 / 方向（建仓·加仓·减仓·申购·赎回，红买绿卖）/ 成交价 / 数量 / 金额（成交价 × 数量）/ 备注。默认按**日期降序**（新→旧），未知日期沉底；同日期下持仓优先。
- **账户 / 平台筛选**：顶部标签由数据自动去重生成（全部 / 股票账户 / 支付宝 / 天天基金 …），点选只看某一来源。
- **金额口径**：持仓按成本价 × 股数（投入成本），基金按成本净值 × 份额（申购本金）。「建仓」为初始持仓基线，日期显示「确切日不详」的是期初录入的持仓。
- **数据来源**：优先读取同源后端的 `/positions.json` 与 `/funds.json`；若以 `file://` 直接打开示例、拉取失败，则回退到前端内置的 `HOLDINGS` / `FUNDS` 数组（含示例 trades）。

### 持仓管理（前端持久化）
- **录入仓位**：模态框填市场/代码/名称/数量/成本/止损/压力位/意图 → 写入 `localStorage` → 合并渲染 + 拉行情。重复代码拦截。
- **卖出减仓**：填卖出数量 + 价格 → 扣减持股、按（卖出价−成本）×数量核算已实现盈亏；减到 0 股自动清仓移除。卖出流水存 `localStorage`，刷新不丢。
- **调整成本/股数**：直接覆盖该持仓的成本价与股数（如补仓后更新均价），浮盈亏等按新值重算。调整记录存 `localStorage`。
- **同步后端**：点「🔄 同步到后端」把前端完整持仓（含录入/减仓/调整后状态）POST 给 `/api/sync`，写回 `positions.json`。

## 搭建步骤

1. **复制示例代码**：将 `assets/workbench.example.html` 与 `assets/workbench-server.py` 放到同一目录。
2. **建立持仓**：在同目录放你的 `positions.json`（从 `assets/positions.template.json` 复制并替换为你的真实持仓；此文件不入库，见 `.gitignore`）。
   - 如需使用养鸡场，再放一份 `funds.json`（从 `assets/funds.template.json` 复制修改）。同样不入库。
3. **启动代理**：`python workbench-server.py`（默认监听 8801）。
4. **打开工作台**：浏览器访问 `http://localhost:8801`。
5. **（可选）修改前端持仓**：若不使用 `positions.json`，也可直接编辑 `workbench.example.html` 里的 `HOLDINGS` 数组（替换为你的标的）。**注意：含真实持仓的文件请勿提交到公开仓库。**

## 数据流与接口

| 前端接口 | 后端行为 | 数据源 |
|---------|---------|--------|
| `GET /api/quotes?codes=sh510300,sz159915` | 批量行情（GBK→UTF-8） | 腾讯 `qt.gtimg.cn` |
| `GET /api/em?path=...` | 东财延迟接口 | 东方财富 `push2delay.eastmoney.com` |
| `GET /api/breadth` | 市场宽度（服务端分页聚合） | 东方财富 clist |
| `GET /api/kline?market=sh&code=510300&lmt=90&klt=d` | K线（日K/周K） | 新浪 `money.finance.sina.com.cn` |
| `GET /api/intraday?code=510300` | 分时数据 | 东方财富 `trends2` |
| `GET /api/fundnav?code=110022,161725` | 批量场外基金单位净值 | 东方财富 `api.fund.eastmoney.com/f10/lsjz` |
| `GET /positions.json` | 读取场内持仓档案 | 本地文件 |
| `GET /funds.json` | 读取场外基金档案 | 本地文件 |
| `POST /api/sync` | 写回场内持仓档案 | 本地 `positions.json` |
| `POST /api/sync_funds` | 写回场外基金档案 | 本地 `funds.json` |

## 持久化与同步模型

```
positions.json（后端权威档案）
        ▲
        │ /api/sync（手动触发，全量写回）
        │
前端 HOLDINGS（运行时）
   ├─ 启动时从 positions.json 加载
   ├─ 合并 localStorage 中的手动录入（wb_manual_positions）
   ├─ 应用调整记录（wb_adjust）覆盖成本/股数
   └─ 应用卖出流水（wb_sells）扣减持股 + 累计已实现盈亏
```

- 前端三份 localStorage（录入/调整/卖出）为**工作副本**，刷新不丢。
- `positions.json` 为**权威备份**，点「同步到后端」后与之对齐。
- 同步语义：`/api/sync` 接收完整持仓列表，匹配到的底层标的仅更新 shares/cost_price/realized_pnl 并保留全部技术面元数据，未匹配的作 `manual` 新增，incoming 中不存在的视为清仓移除。

## 合规与脱敏

- 工作台仅为**个人信息整理工具**，不含投顾逻辑、不自动下单、不输出买卖建议。
- 示例代码中所有持仓均为**虚构数据**，与任何真实账户无关。
- 含真实持仓的 `positions.json`、`funds.json` 与个人版 `workbench.html` 已在 `.gitignore` 中排除，请勿提交到公开仓库。
- 改后端 `.py` 后需**重启代理服务**才会生效（Python 进程启动时一次性加载代码，不会热更新）；改前端 `.html` 只需浏览器刷新。

## 常见坑点

| 现象 | 原因 | 解决 |
|------|------|------|
| 页面白屏 / 连不上 | 代理服务未启动或已退出 | `python workbench-server.py` 重启 |
| 行情获取失败 | 数据源限流或网络问题 | 前端显示快照价兜底，60s 后自动重试 |
| 同步后端无反应 | 改了 `.py` 未重启 | 停掉旧进程再重启（端口 8801） |
| K线弹窗空白 | 新浪/东财接口偶尔不可达 | 切换视图或稍后重试 |
| 改了后端代码不生效 | 旧进程仍在内存跑旧代码 | 必须停旧进程、重启 |
| **静态页正常但所有 `/api/*` 报 `WinError 10061 目标计算机积极拒绝`** | Windows 下 `urllib` 会自动读注册表的**系统代理**配置，该代理端口未运行时请求全部被拒。`curl` 不读注册表，所以命令行直连正常——极易误判为"服务挂了" | 已在示例 server 中修复：模块级 `OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))`，转发时用 `OPENER.open()` 绕过系统代理。**排查口诀：curl 直连通 + 服务报 10061 ⇒ 代理问题，不是网络问题** |
| 养鸡场净值全部拉不到 | 旧接口 `fundgz.1234567.com.cn` 的实时估值已停止服务 | 改用东财 `api.fund.eastmoney.com/f10/lsjz`（示例 server 已采用） |
| 养鸡场净值偶发缺失 / 状态显示获取失败 | 后端对基金逐只串行请求，基金数量多时整体耗时随只数线性增长 | 属预期行为，稍后自动重试；基金数量较多时首次加载需要等待，前端会先用录入价兜底显示 |
